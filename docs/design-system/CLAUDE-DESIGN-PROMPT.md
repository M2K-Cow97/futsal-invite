# 클로드 디자인 요청 프롬프트

아래 블록을 **그대로 복사**해서 클로드 디자인에 붙여넣으세요.
`docs/design-system/CLAUDE.md` 를 함께 첨부하면 토큰이 정확히 반영됩니다.

받은 결과물을 이 저장소에 반영할 때 필요한 형식까지 요구하도록 짜여 있습니다 —
그림만 받으면 개발자가 눈으로 보고 추측해서 옮기게 되므로, **수치와 클래스명을
같이 받는 것**이 핵심입니다.

풋살 초대장 웹앱(Next.js)의 모바일 화면을 디자인해줘.
결과를 실제 코드베이스에 그대로 반영해야 하므로, 아래 "산출물 형식" 을
반드시 지켜줘. 예쁜 이미지만으로는 반영할 수 없어.

호날두 페르소나로 일관한다. UI 자체는 담백하고, 유머는 문구로만 낸다.

3. 규칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 모바일 390×844 (iPhone) 기준, 라이트 테마. 320px 에서도 깨지지 않게.
- 토스처럼 정보 위계가 분명하고 여백이 넉넉하게.

- 터치 타깃 최소 44×44.

■ 게스트 흐름
1. 초대 첫 화면
   "문경덕이(가) 물어봐요"(작게·흐리게) / "나랑 풋살할래?"(크게)
   / 경기 정보 2행(언제: 11월 5일 (목) 20:00 / 어디서: 강남 풋살장)
   / "거절은 물리적으로 불가능합니다" / [좋아!] 초록 + [싫어.] 작게
   ※ [싫어.] 는 누르려 하면 도망가는 버튼이다. 아래쪽에 여유 공간이 필요.
2. SIUUU 축하 — 정사각 이미지(호날두 세리머니) + "나도 좋siuuuuu" + [참석 확정하기]
3. 참석 확인 — 구장 사진(16:9) / 날짜·시간·구장·경기링크 목록 4행
   / 이름 입력 / [참석할래!]
4. 포지션 선택 — 2×2 카드(공격수·미드필더·수비수·골키퍼).
   각 카드: 이름 / 약어(FW) / 인원 뱃지("비어 있음" 또는 "2명")
5. 확정 티켓 — 어두운 티켓(#11130F). 상단 "FUTSAL MATCH / CONFIRMED",
   본문에 DATE·KICK-OFF·STADIUM·POSITION·PLAYER 5행(점선 구분).
   하단 [이미지 저장] [나도 만들기]
   ※ 캡처해서 자랑하는 결과물이라 가장 완성도 높게.

9. 빈 상태 — 참석자 0명일 때

■ 거절 관문 (모달)
11. 모달 껍데기 — 작은 pill 뱃지("거절 심사") / 제목 / 설명 / 콘텐츠 영역
    / 하단 버튼 줄. 배경은 어둡게 덮는다.
12. 사유 선택 리스트 — 6개 항목(부상이야·그날 약속 있어·돈이 없어·실력이 안 돼

    이미 기각된 항목은 흐리게 + 취소선 + "기각" 표시.
    목록이 길어 스크롤되니 잘리는 지점 처리도.
13. 심사 진행 — 단계 목록(체크·진행중·대기 3상태)
14. 판정 결과 — 판정 제목 / 설명 문단 / 도장처럼 기울어진 강조 배지
15. 훈시(마지막) — 어두운 벽 배경에 자막이 한 줄씩 쌓인다.
    "단어 알지?" / "FUTSAL"(거대한 흰 대문자, 붉은 잔상) /
    "오늘 풋살장 나가서 풋살해." / "나는 오늘 그거, 볼 거야."
    지나간 줄은 흐려진다. + [다음] / 마지막엔 [ …네 ]

각 화면마다 아래 3개를 모두 줘.

(A) 시안 이미지
    - 화면당 1장. **가로 1500px 이하** 로 내보내줘(그보다 크면 개발
      단계에서 열어볼 수 없다).
    - 실제 한국어 텍스트를 채워라. Lorem ipsum·영문 더미 금지.

(B) 스펙 표 — 눈대중으로 옮기지 않게, 수치를 표로 적어줘
    | 요소 | 값 |
    |---|---|
    | 폰트 크기/행간/굵기 | 예: 28 / 35 / 700 |
    | 색 | 예: #11130F (텍스트 기본) |
    | 위쪽 여백 / 아래 여백 | 예: 24 / 8 |
    | 크기 | 예: 높이 56, radius 12 |
    ※ 색은 **위 토큰 목록의 값**으로만 적어라. 새 색을 썼다면
       "신규: #XXXXXX (용도)" 로 따로 표시.
    ※ 간격은 4/8/16/24/40/48 중에서. 벗어났다면 이유를 적어라.

(C) 기존 클래스와의 매핑
    이 앱은 CSS 클래스 기반이다(Tailwind 아님). 아래가 현재 쓰이는
    클래스 이름이니, 각 요소가 어느 클래스에 해당하는지 적어줘.
    새 요소라면 "신규: .클래스명" 으로 제안해라.

    티켓      .ticket .ticket-head .ticket-body .ticket-row .ticket-actions
    주최자    .link-box .link-label .link-desc .link-row .link-url
              .counts .count-cell .count-pos .count-num .roster .guest
              .pos-tag .empty .skeleton
    모달      .modal-backdrop .modal .modal-text .modal-actions
    관문      .reject-modal .reject-head .reject-badge .reject-title

    사유      .reason-list .reason-item .reason-emoji .reason-label .reason-mark

    훈시      .lecture-board .lecture-line .lecture-count

(D) 변경 요약
    화면별로 "지금과 무엇이 달라지는지" 를 3줄 이내로.
    (개발자가 무엇을 고쳐야 하는지 바로 알 수 있게)

6. 하지 말아야 할 것

- 새 색·새 폰트·새 radius 값을 임의로 만들지 마라. 필요하면 명시해라.
- #00E061 위에 흰 글자를 올리지 마라.

## 받은 뒤 개발자에게 전달하는 방법

1. **스펙 표(B)와 매핑(C)을 텍스트로** 그대로 붙여주세요 — 이게 있으면 추측 없이 반영됩니다.
2. 시안 이미지는 **화면 하나씩** 주시면 순서대로 적용합니다.
3. 이미지가 1500px을 넘으면 읽을 수 없으니 리사이즈가 필요합니다.
