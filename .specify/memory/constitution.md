# futsal-invite Constitution

풋살 초대장 웹앱. 원본 기획(`docs/2026-08-08-design.md`, `docs/기획-목업-전체.png`)의
"장난스러운 초대장" 톤을 유지하면서, 링크 공유로 실제 참석자를 모으는 서버 기반 앱으로 확장한다.

## Core Principles

### I. 목업이 진실이다 (NON-NEGOTIABLE)

5개 화면(invite / siuuu / matchday / position / ticket)의 순서, 문구, 인터랙션은
원본 목업이 정의한 그대로 구현한다. 개선 아이디어가 있어도 목업과 충돌하면 목업을 따른다.

- 화면 문구는 목업의 한국어를 그대로 사용한다 ("나랑 풋살할래? ⚽", "나도 좋siuuuuu 🔥", "포기해." 등)
- "싫어." 버튼 회피, 3회 후 문구 변경, 공격수 2단 팝업은 재미의 핵심이며 생략 불가
- 색상/레이아웃은 목업의 다크 그린 + 크림 카드 조합을 따른다

### II. 링크 하나로 완결된다

주최자는 링크를 만들고, 초대받은 사람은 링크만 열면 끝난다.
회원가입·로그인·앱 설치·설명 없이 동작해야 한다.

- 초대받는 사람에게 인증을 요구하지 않는다
- 주최자도 계정을 만들지 않는다. 관리 링크(비밀 토큰)를 아는 것이 곧 권한이다
- 링크는 카카오톡에 붙여도 깨지지 않게 짧고 OG 미리보기를 가진다

### III. 서버는 최소한만 한다

서버의 존재 이유는 "여러 사람이 같은 초대장을 본다" 하나뿐이다.
그 외 모든 것은 클라이언트에 둔다.

- 애니메이션·사운드·화면 전환은 100% 클라이언트
- API는 초대장 생성/조회, 응답 등록/조회만 제공한다
- 상태 관리 라이브러리, 전역 스토어, 캐시 레이어를 도입하지 않는다

### IV. 무료 티어를 벗어나지 않는다

카드 등록 없이 무료로 계속 운영 가능해야 한다.

- Vercel Hobby + Neon Free 한도 안에서 설계한다
- Neon 은 유휴 시 자동 대기(cold start)한다. 첫 요청 지연을 UX 로 흡수한다 (스켈레톤/로딩)
- 크론, 백그라운드 워커, 상시 연결(WebSocket)을 쓰지 않는다. 갱신은 폴링 또는 재방문으로 해결

### V. 개인용 장난 페이지의 보안 수준

외부 공개 서비스가 아니다. 과도한 방어는 하지 않되, 남의 초대장을 망칠 수는 없어야 한다.

- 관리 토큰은 추측 불가능한 길이(최소 128비트 엔트로피)
- 서버는 모든 입력을 스키마 검증한다 (길이 제한, 타입, 날짜 범위)
- 사용자 입력은 항상 텍스트로 렌더링한다. `innerHTML` 로 넣지 않는다
- 인증·권한·감사로그·rate limit 정교화는 범위 밖. 단순 IP 기반 상한만 둔다

## 기술 제약

- **프레임워크**: Next.js (App Router) — 프론트와 API 를 한 배포 단위로
- **DB**: Neon Postgres, 접근은 Drizzle ORM 경유. 생 SQL 문자열 조립 금지
- **이미지 저장**: `html2canvas` (원본 기획 유지)
- **빌드 산출물**: Vercel 이 자동 빌드. 로컬 빌드 결과물을 커밋하지 않는다
- **에셋 부재 허용**: siu.gif / 사운드 / 호날두 이미지가 없어도 이모지·플레이스홀더로 동작한다

## 개발 워크플로우

- spec-kit 단계(constitution → specify → plan → tasks → implement)를 순서대로 밟고 산출물을 남긴다
- 모든 구현 작업은 `specs/001-*/tasks.md` 의 태스크에 대응한다
- 자동화 테스트는 API 계약(초대장 생성/응답)에만 작성한다. UI 애니메이션은 수동 확인
- 검증 기준: 5개 화면 전체 흐름 + 링크 공유 후 타인 응답이 주최자 화면에 보이는 것

## Governance

이 헌법은 다른 모든 판단에 우선한다. 원칙과 충돌하는 구현은 원칙을 고치거나 구현을 고친다.
어느 쪽이든 명시적으로 기록한다. 복잡도를 늘리는 결정은 근거를 `plan.md` 에 남긴다.
